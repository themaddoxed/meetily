## Behavior

The meeting details page offers a question field and displays the configured provider, model and local/network transport. Network requests require consent for the current configuration fingerprint. Changing configuration clears that consent. Only the selected meeting title and transcript enter the prompt; an oversized context is rejected rather than silently truncated. Empty context reports insufficient evidence without invoking a generator.

Answers use a strict structured contract. Each claim must cite a selected-meeting transcript ID and a literal excerpt; source links are generated by the application and open the existing deep transcript anchor. Unknown IDs, fabricated excerpts, extra fields and malformed responses are rejected. This checks attribution, not semantic entailment: real-model faithfulness remains FEAT-102.

A meeting edit or deletion during generation invalidates the answer. Cancellation, selection changes and late responses preserve request identity. HTTP cancellation covers headers and the full response body. Built-in questions own a separate sidecar with bounded kill/reap cleanup; they do not use the global summary manager. Configuration refresh cannot be interrupted by the generation cancel button.
