# Срочные macOS-задачи: порядок, статус и оставшиеся проверки

Базовый опубликованный snapshot перед добавлением этого отчёта: `325217617e1c1f15dc8b954d6e7c2c9c4cf33faf`

Этот документ фиксирует рабочий порядок для пяти срочных задач, уже сделанные части и доказательства, которых ещё не хватает для закрытия. Успешный тест Rust, браузерный mock или проверка структуры DMG не заменяет запуск приложения macOS с реальными разрешениями и устройствами.

## Порядок выполнения

### 0. Зафиксировать общие предпосылки

До финальной приёмки нужно определить окончательное имя приложения, уникальный `bundle ID` и целевые каталоги данных. `bundle ID` — это постоянный идентификатор приложения macOS; от него зависят перенос профиля, подпись и updater.

Также нужно закрыть прямые зависимости из графа: `FORK-034` для permission/lifecycle, `FORK-056` для updater и остальные обязательные задачи Alpha. Без окончательного идентификатора нельзя честно проверить миграцию и подписанное обновление.

### 1. FORK-051 — разрешения macOS и жизненный цикл микрофона

**Сделано:**

- добавлен асинхронный запуск CoreAudio;
- добавлен безопасный microphone-only fallback, если системный источник недоступен;
- исправлены pause/resume, stop и quiesce при завершении;
- добавлено восстановление после ошибки микрофона;
- исправлена terminal state у writer;
- добавлены active-time timeline, pause epochs и заполнение разрывов тишиной;
- подготовлены permission coordinator, UI/service-контур и автоматические тесты;
- подтверждены отдельные native циклы Start → Pause → Resume → Stop/Exit на предыдущих exact-пакетах.

**Осталось:**

- запустить именно актуальный `.app` после последних изменений;
- проверить матрицу разрешений macOS: разрешение, отказ, возврат из Settings и повторный запрос;
- проверить отключение и повторное подключение физического микрофона;
- проверить обычный Quit во время записи на текущем пакете;
- подтвердить, что текущий пакет действительно создаёт ожидаемые аудиофайлы.

`TCC` в этом контексте — системная база разрешений macOS. Последний текущий `.app` намеренно не запускался, поэтому новые permission prompts не вызывались и этот gate остался открытым.

**Критерий закрытия:** один воспроизводимый native-сценарий на текущем `.app` с разрешением, отказом и восстановлением доступа, физическим reconnect и корректным завершением записи.

### 2. FEAT-071 — единое управление микрофоном и системным звуком

Задача зависит от FORK-051 и должна приниматься после него.

**Сделано:**

- добавлены отдельные состояния для microphone и system audio;
- добавлены mute и gain для каждого источника;
- управления применяются к downstream-пути, а raw Track сохраняется без изменения;
- добавлена общая шкала времени для обеих дорожек;
- учтены pause/resume и reconnect gaps;
- добавлены UI, Tauri-команда и сервисные тесты;
- автоматические Node, Vitest, Playwright и Rust-проверки проходят.

**Осталось:**

- получить реальный `system.mp4` на текущем `.app`;
- записать разнесённые контрольные сигналы и проверить совпадение времени;
- проверить native mute и регулировку громкости;
- проверить синхронность после pause/resume;
- проверить повторную обработку исходных дорожек.

**Критерий закрытия:** текущий `.app` создаёт обе дорожки, mute/gain меняют только выбранный источник, pause/resume не сдвигает время, а raw tracks остаются пригодными для повторной обработки.

### 3. FORK-037 — перенос пользовательских данных при смене bundle ID

**Сделано:**

- реализованы манифест, контрольные суммы и безопасные относительные пути;
- добавлены no-clobber публикация, журнал этапов, блокировка и возобновление;
- добавлена проверка свободного места через `statvfs`;
- реализован SQLite snapshot для `main`, `-wal` и `-shm`;
- добавлены read-only reopen и immutable-проверка;
- подключён startup guard для незавершённых migration journals;
- зарегистрированы публичные команды `prepare_profile_migration`, `publish_profile_migration` и `get_profile_migration_status`;
- реализованы IndexedDB source/sink и transactional marker;
- migration suite и общий автоматический gate проходят.

**Осталось:**

- подключить команды к реальному startup-потоку приложения;
- закончить пользовательский export/import через WebView;
- зафиксировать старый и новый bundle ID;
- выполнить настоящий upgrade со старым профилем в новую установку;
- проверить meetings, transcripts, SQLite WAL, IndexedDB, marker, readback и повторный запуск;
- подтвердить отказоустойчивость без перезаписи существующих данных.

В ходе этой работы пользовательские данные не читались и не изменялись.

**Критерий закрытия:** тестовый старый профиль переносится в новую установку с другим bundle ID, данные открываются, контрольные суммы совпадают, повтор не создаёт дублей, а сбой на любом этапе можно безопасно продолжить или откатить.

### 4. FORK-036 — новый подписанный updater

**Сделано:**

- политика updater остаётся fail-closed;
- есть проверки запрета небезопасного обновления;
- определены ограничения обновления во время активной записи.

**Осталось:**

- выбрать окончательный bundle ID и канал распространения;
- получить рабочую Developer ID identity;
- настроить подписанный update feed;
- проверять подпись и целостность до установки;
- добавить rollback, совместимость архитектур и понятные состояния progress/error/defer/skip;
- запретить обновление во время записи;
- провести end-to-end проверку подписанного и notarized обновления.

На текущем хосте команда `security find-identity -v -p codesigning` показала `0 valid identities found`, поэтому этот gate пока нельзя закрыть локальной диагностической подписью.

**Критерий закрытия:** подписанный пакет принимается только после проверки подписи, корректно обновляется на Intel и Apple Silicon, умеет откатиться и не прерывает активную запись.

### 5. FORK-052 — recovery, offline и upgrade

Эта задача не входит в исходную пятёрку, но напрямую блокирует Alpha.

Нужно проверить на отдельном тестовом профиле:

- crash/relaunch на стадиях capture, transcribe, diarize и summarize;
- offline-режим;
- смену папки записи;
- повторный запуск без дублей;
- сохранность raw audio и завершённых результатов;
- совместимость после обновления.
