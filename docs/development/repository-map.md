# Структура проекта и происхождение работ

Снимок навигации: 18 октября 2026. Вход в проект — [корневой индекс](../../INDEX.md).
Состояние кода, незакоммиченные изменения и результат проверки — разные сведения.
Ни перенос документов, ни наличие отчёта с PASS не закрывают продуктовую задачу.

## Что хранится отдельно от исходников

`.worktrees/` содержит самостоятельные checkout и резервные материалы. Каталог
не является папкой для уборки. Некоторые checkout находятся вне проекта, в
`~/.codex/worktrees/`; полный снимок приведён в
[реестре рабочих деревьев](worktree-inventory.md).

`.git/` хранит историю и refs; `.beads/` — локальное служебное состояние старого
инструмента. `.beads.gate.lock` — lock-файл, а не задача. `.pnpm-store/`,
`node_modules/`, `target/`, `frontend/.next/`, `frontend/out/`,
`frontend/test-results/`, модели, бинарники и локальные логи — зависимости либо
результаты выполнения. Индекс перечисляет их назначение без обхода содержимого.
Секреты, пользовательские базы, записи и профили не входят в каталог проекта.
`artifacts/release-gate/` — предусмотренное существующими скриптами хранилище
локальных release-свидетельств; его отсутствие не означает успешный gate.

## Как определить, кто что сделал

1. Для коммита использовать `git log -- <path>` и точный SHA. Автор последнего
   коммита не обязательно является автором последующих локальных правок.
2. Для ревью использовать указанного в самом документе автора. Например,
   `/root/plans_quality` — историческая метка агента, а не назначенный сейчас
   исполнитель и не доказательство человеческого авторства.
3. Если авторство незакоммиченных правок не записано, считать его неизвестным.
   Не выводить его из имени ветки, файла или владельца компьютера.
4. При передаче результата записывать task ID, исполнителя/агента, рабочее
   дерево, base и конечный commit либо хеши файлов, изменённые пути, реально
   выполненные проверки, ограничения и следующий шаг. Не назначать нового
   владельца без фактического принятия работы.

[Снимок до реорганизации](evidence/2026-10-18-workspace-before.json) содержит
хеши файлов, последнее зафиксированное авторство и исходное состояние рабочих
деревьев. Для новых материалов этой реорганизации исполнитель — Codex в текущем
чате, область — документация и навигация, база — `53f4415058fb01e38b8892a47ac036bfffa394ba`.
Коммит для этих изменений не создан.

## Старые пути и контрольные суммы

[Таблица перемещений](evidence/2026-10-18-structure-moves.json) хранит для каждого
из 155 файлов `from`, `to`, SHA-256, известное Git-авторство и метки агентов.
Перенесённые планы, census, ревью и иллюстрации сохранены побайтно. Поэтому
старый SHA документа проверяется по новому пути без изменения его содержания.

Исторические строки путей внутри JSON, отчётов и планов оставлены как часть
исходного свидетельства: если старый путь отсутствует, найти его в `moves[].from`
и читать `moves[].to`. Ссылки на определённый Git commit сохраняют исторический
смысл. Markdown-ссылки действующих PRD и входных документов обновлены. Отсутствие
старого временного лога в `/private/tmp` нельзя исправить переписыванием PASS:
для нового доказательства нужна повторная проверка и новый отчёт.

Старые `docs/fork/migration-registry.md` и `docs/fork/git-policy.md` описывают
свой этап истории. Для текущих ролей `main`/`dev` использовать
[Git workflow](git-workflow.md) и свежий `git worktree list`; старые команды
с конкретными именами checkout не выполнять автоматически.

## Обновление индекса

После добавления, переноса или удаления проектных файлов выполнить
`python3 scripts/project-index.py`, затем `python3 scripts/project-index.py --check`.
Скрипт обновляет только каталог файлов в конце `INDEX.md`; описания направлений,
статусы и назначение папок требуют осмысленной правки. Снимки от 18 октября
сохраняются как история, а следующий аудит получает новую дату.
