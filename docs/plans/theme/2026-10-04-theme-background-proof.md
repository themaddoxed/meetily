## Observed problem and unchanged acceptance

All three current background cases failed (exit 1, zero passes) because the Sidebar expand button intersects the rectangle of a containing layout element. Report `/private/tmp/meetily-theme-background-current.json` records this geometry failure, not a detected near-white color. Large containers contain descendants with different paints: demanding one uniform rendered background for their entire rectangle is inappropriate for proving absence of light surfaces. The exact text/focus resolver is still appropriate for its small measured regions and stays unchanged.

Success criterion 6 remains: actual Home, Settings and Meeting Details have no near-white app background island in dark mode, plus no horizontal overflow. No transient semantic probe can satisfy it. A background is near-white when all RGB channels are at least 245, as in the existing suite. The new proof is stronger: certify an upper bound below 245 for *every* RGB channel across the complete main rectangle, including overlapping and translucent background layers. An inconclusive bound fails rather than passing. Retain the existing deliberate checked-switch background exception, explicitly report its nodes; do not add another exception. Text, meaningful icon/indicator foregrounds and borders are separate acceptance subjects, not background layers. A white box-shadow remains background paint and cannot use that switch exception.

## Scope and interface

Only the already admitted `frontend/tests/helpers/rendered-contrast.ts` and `frontend/tests/theme-dark-surfaces.spec.ts` may change. Add a separate browser-evaluated background absence function in the shared helper and use it in the three existing route checks. Do not extend the text/focus `measureRenderedContrast` modes or reuse shadow certificates. No product, dependencies, config, snapshot or additional implementation path. Read current computed styles and geometry synchronously within one browser evaluation; return a compact ledger including scope rectangle, checked-control exceptions, number of background layers/cells, maximum bound/location and unsupported effects.

The old point/region contrast fixtures and text/focus callers continue to require the exact resolver and fail closed for gradients and ambiguous paint. The amendment changes only the background-island proof, where a safe upper bound suffices to prove absence without asserting one exact composite color.

## Conservative paint inventory

Require one `main` and an explicit opaque HTML canvas with root opacity 1. Start the bound at the maximum RGB channel of that canvas. Collect every positive-area rendered DOM element whose background can intersect the main rectangle, including descendants, ancestors and foreign positioned elements. Do not filter on background alpha or on a minimum area. Include offscreen parts of main; do not limit coverage to the visible screenshot. Respect display/visibility and ancestor opacity only when zero paint is established. Use DOM bounding rectangles as conservative supersets; do not discard paint because of rounded corners or clipping.

For each solid background, retain its maximum RGB channel, alpha, conservative rectangle and product of node/ancestor opacities. Transparent backgrounds contribute zero, but their other paint properties still need validation. Handle a background fill and its image as separate potential layers. Support only ordinary `linear-gradient` with a direction/angle and computed sRGB `rgb`/`rgba` color stops (optional simple percentage stops). Reject every URL/image, radial/conic/repeating gradient, multiple images, interpolation-space modifier, unknown color syntax or other unsupported grammar. For a supported gradient, maximum source channel and maximum stop alpha over all stops are upper bounds; treating these independent maxima as one uniform layer over its full rectangle overestimates the actual paint and is safe. No gradient becomes accepted for text/focus contrast.

Parse every box-shadow color/layer, including inset: its maximum source channel and effective alpha are bounds. Treat its extent as the whole main rectangle, avoiding a finite-blur cutoff or an assumed shadow rasterizer. This may be inconclusive for bright shadows, which must fail. Dark shadows cannot increase the bound. Validate pseudo-element background/image/shadow paint too; if its geometry cannot be established, conservatively cover the whole main rectangle. Generated foreground text is not a background fill. Replaced media/canvas/iframe or unsupported pseudo paint must fail, not be silently omitted.

Reject non-normal blending, filters/backdrop filters, masks/clip-path ambiguity, unsupported transforms/zoom, non-finite values and any unsupported effect. Preserve the existing translation-only coordinate contract. Position/z-index do not themselves require rejection: the bound deliberately considers every possible order of the supported layers.

## Bound calculation and soundness

Split the main rectangle at every collected background rectangle boundary, clipped to the scope. Each resulting open rectangular cell has a constant set of possible background layers. Also cover boundaries by conservative closed rectangle intersection; never certify a cell while omitting a boundary-only layer. Use conservative inclusion where an effect's geometry is unknown.

For a cell, let `u` be its scalar channel upper bound. A possible layer with source maximum `c` and effective alpha `a` can only raise it to `u + max(0, c - u) * a`; dropping layers that would darken the result is conservative. Process source maxima in ascending order to maximize the result across possible stacking orders. This deliberately overestimates independent child contributions inside opacity groups: treating each contribution separately at the product opacity does not create a lower bound. Explain/prove this group-opacity property in the implementation review, including nested groups and an external sibling layer. If this property cannot be established, do not implement the simplification: use a group-aware bound instead.

Use full floating-point values with an explicit upward error margin per operation; define finite caps for nodes, layers, cells and operations so total rounding error stays well below the margin. Exceeding a cap is unresolved/FAIL. Never round the comparison downward, use a percentile, sample sparse points or mask pixels. A result at/above 245 or unsupported/inconclusive scene fails the route check. Record the brightest bound and contributing layers to distinguish a real light island from a conservative failure. Every supported actual channel is bounded by `u`; therefore `u < 245` proves absence of the original all-channels-near-white island criterion.
